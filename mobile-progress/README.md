# 한 장씩 · 모바일 성경 읽기 기록

기존 성경 뷰어를 보존하면서 분리한, 성경 본문 없는 모바일 PWA입니다. `mobile-progress/`만 복사해 독립적으로 사용할 수 있습니다. 원본 `src/`, 데이터, 설정, 기존 저장 키를 변경하지 않습니다.

## 포함한 기능

- 오늘: 66권 1,189장 중 읽은 비율, 남은 분량, 다음 미완료 장 추천, 완료 기록과 되돌리기
- 읽기 기록: 구약·신약, 권 검색, 장별 체크·취소, 이미 읽은 구간 일괄 등록
- 계획·계산: 목표일까지 필요한 하루 분량, 개인 페이스에 따른 예상 완독일, 어디까지/총 몇 장/연간 회독 계산
- 설정: 홈 화면 설치 안내, JSON 백업·복원, 초기화
- 앱 셸과 계산·기록의 오프라인 사용. 성경 본문 및 본문 다운로드는 포함하지 않습니다.

## 실행

Node.js 20.19+, 22.12+ 또는 24 이상을 사용합니다. 이 폴더의 `package.json`과 `package-lock.json`으로 의존성을 독립 관리하며, 상위 폴더의 `node_modules`는 필요하지 않습니다.

```sh
cd mobile-progress
npm ci
npm run dev
```

`mobile-progress/`만 다른 위치로 복사해도 동일하게 실행할 수 있습니다. `node_modules/`와 `dist/`는 복사하지 않아도 됩니다. 복사한 폴더에서 `npm ci`로 잠금 파일의 버전을 설치한 뒤 실행하거나 빌드하세요. React, Vite, PWA 플러그인, Lucide 등은 이 폴더의 `node_modules/`에 설치됩니다.

개발 주소: `http://localhost:5204`. 같은 Wi-Fi의 휴대폰에서는 실행 시 출력되는 Network 주소로 미리 볼 수 있습니다. 컴퓨터가 켜져 있고 방화벽에서 접근을 허용해야 합니다. **LAN의 HTTP 주소는 화면 확인용이며 PWA 설치·오프라인 검증용이 아닙니다.**

```sh
npm test
npm run lint
npm run build
npm run preview
```

`dist/`가 배포 결과입니다. 개발 서버에는 서비스 워커가 없으므로 오프라인 동작은 프로덕션 빌드의 preview 또는 HTTPS 배포 주소에서 확인합니다.

## 휴대폰에서 실제 사용하기

이 용도에는 네이티브 앱보다 **설치형 웹 앱(PWA)**을 우선 선택했습니다. 로그인이나 전용 기기 기능 없이 진도 체크와 계산을 하는 앱이므로 하나의 코드로 iPhone과 Android를 지원하고, 앱스토어 심사 없이 관리할 수 있습니다. 네이티브 앱은 추후 앱스토어 배포나 보다 깊은 OS 통합이 필요해질 때 검토하면 됩니다.

1. `npm run build`로 만든 `dist/`의 내용을 정적 HTTPS 호스팅에 배포합니다. 빌드 명령은 `npm run build`, 출력 폴더는 `dist`이며 프로젝트 기준 폴더는 `mobile-progress`입니다.
2. 기존 앱의 서비스 워커와 저장 영역이 섞이지 않도록 **별도 서브도메인 또는 별도 사이트** 사용을 권장합니다. 새 앱의 HTML과 `sw.js`에는 장기 캐시를 걸지 않습니다.
3. iPhone: Safari에서 배포 주소 열기 → 공유 메뉴 → 홈 화면에 추가.
4. Android: Chrome에서 배포 주소 열기 → ⋮ 메뉴 → 앱 설치/홈 화면에 추가. 지원되는 환경에서는 설정 화면의 설치 버튼도 표시됩니다.
5. 처음 온라인에서 앱이 준비된 다음 오프라인으로 다시 열어 확인합니다.

공개 배포는 수행하지 않았습니다. 배포 계정이나 목적지가 지정되지 않아 기존 서버·도메인 설정도 바꾸지 않았습니다. 실물 iPhone/Android의 설치는 별도로 확인해야 합니다.

참고: [MDN PWA 설치 안내](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Installing), [Apple 홈 화면 웹 앱 안내](https://support.apple.com/guide/iphone/open-as-web-app-iphea86e5236/ios), [Google 오프라인 PWA 안내](https://web.dev/learn/pwa/getting-started).

## 기록과 계산 규칙

- 저장 키는 `bible-mobile-progress-v1`. 장별 완료 기록과 목표를 해당 기기·브라우저의 localStorage에 저장합니다. 서버 전송이나 자동 기기 동기화는 없습니다.
- 시작 장과 끝 장은 포함합니다. 분량 계산기는 요한계시록을 넘으면 창세기로 돌아갑니다. 완료 구간 등록은 한 회독 안에서만 하며 끝은 시작 이후여야 합니다.
- 하루 분량 계산에 오늘을 포함합니다. 목표일이 지났으면 날짜 재설정을 안내합니다. 날짜는 사용자 기기의 현지 날짜 기준이며, 월·연도·윤년·서머타임 경계를 고려합니다.
- 시작 위치는 오늘의 ‘시작 위치·목표 변경’ 또는 계획·계산의 ‘읽기 시작 위치’에서 권·장을 선택하고 ‘목표 저장’을 눌러 변경합니다. 추천 분량은 설정한 시작 장부터 아직 완료하지 않은 장을 성경 순서대로 선택하며, 요한계시록 이후에는 창세기로 이어집니다. 시작 위치 변경은 완료 기록에 영향을 주지 않습니다. 기존 기록·백업에 시작 위치가 없으면 창세기 1장으로 적용합니다. 건너뛰어 읽은 기록이 있으면 이미 완료한 장은 제외합니다. 한 회독의 진도이며 날짜별 독서 일지나 누적 여러 회독 통계는 아닙니다.
- 원본의 `bible_reading_progress`는 마지막 **열람 위치**일 뿐 완료한 장 목록이 아닙니다. 자동으로 완료 처리하지 않습니다. 기존 계산 내역·북마크도 자동 이관하지 않으며, 원본에 그대로 남습니다.
- 브라우저 데이터 삭제, 비공개 모드 종료, 저장소 정리로 기록이 사라질 수 있습니다. 백업 파일을 보관하고 다른 기기나 브라우저에서는 복원하세요. 홈 화면 앱으로 이동하기 전에도 백업을 권장합니다.
- 손상된 저장 데이터는 시작할 때 덮어쓰지 않습니다. 설정에서 원본을 내려받을 수 있습니다. 저장에 실패하면 기록 성공으로 표시하지 않습니다. 초기화·복원은 확인 후 진행합니다.

## 검증과 유지보수

계산·저장 형식 단위 테스트: `npm test`. 미국 뉴욕 서머타임 조건: `TZ=America/New_York npm test`.

브라우저 검증은 기존 환경의 Playwright를 재사용하므로 앱 의존성에 추가하지 않았습니다. 다른 환경에서는 설치된 Playwright의 `index.mjs` 절대 경로를 전달합니다. 먼저 빌드와 preview 서버를 실행합니다.

```sh
node scripts/browser-check.mjs /absolute/path/to/playwright/index.mjs
```

검증 범위: 기록·취소·구간 등록·새로고침, 목표, 계산기, 320/390/430/1024px 가로 넘침, 백업·복원·손상 파일, 오프라인 새로고침·기록, 손상된 저장 원본 보호, 브라우저 실행 오류. 테스트는 격리된 새 브라우저 컨텍스트에서 실행합니다. 화면 캡처는 `qa/`에 있습니다.

아이콘은 로컬 SVG로 만든 정적 자산입니다. 다시 생성하려면 위 명령 끝에 `icons`를 붙입니다. 본문 데이터와 원본 앱은 빌드에 포함되지 않습니다.
